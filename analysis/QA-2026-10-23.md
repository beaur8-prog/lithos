# Lithos 1.0.1 사용자 시나리오 검수

검수일: 2026-10-23. macOS Apple Silicon에서 설치된 1.0.0과 수정한 1.0.1을 비교했다. 실제 창에서 입력·클릭·단축키를 사용하고, 저장된 파일과 자동 테스트로 결과를 확인했다. 별도 보관함과 앱 프로필을 사용했으며 사용자의 실제 노트와 실행 중인 공유 서버는 변경하지 않았다.

## 발견한 문제와 수정

### 보기·탭 전환 후 실행 취소 이력 소실

재현: 본문을 수정한 뒤 읽기 모드로 전환하고 원본 모드로 돌아와 `⌘Z`를 누른다. 다른 노트 탭에 갔다 오는 경로에서도 이전 수정의 실행 취소가 사라졌다.

원인: 읽기 모드와 노트 전환 과정에서 CodeMirror를 제거하고 새 편집 상태를 만들면서 문서별 이력과 선택 영역이 초기화됐다.

수정: 노트별 편집 상태를 보관하고 같은 내용의 노트를 다시 열 때 복원한다. 읽기 모드는 편집기를 유지한 채 표시와 설정을 전환한다. 체크박스와 서식 변경도 개별 실행 취소 단계로 기록한다. 외부 파일 변경은 새 상태로 불러와 오래된 실행 취소로 덮어쓰지 않게 한다.

재검증: 읽기 왕복 후 실행 취소·다시 실행, 탭 왕복 후 실행 취소, 읽기 화면 체크박스 변경 후 실행 취소가 동작했다.

### 대용량 문서의 읽기 미리보기 멈춤

재현: 약 8.1MB, 186,003줄의 한글·영문·이모지 문서를 열고 읽기 모드로 전환한다. 기존 버전은 전체 Markdown 미리보기를 만들면서 창이 응답하지 않았다. 당시 기록한 렌더러 관측값은 CPU 129.2%, RSS 1,009,680 KiB였다. 이는 특정 시점의 관측값이며 일반적인 성능 보장은 아니다.

원인: 문서 전체를 Markdown DOM으로 렌더링했고, 실시간 꾸밈과 링크·태그·개요 계산도 불필요하게 반복했다.

수정: 1,048,576 UTF-16 코드 단위 또는 10,000줄을 넘는 노트는 화면에 필요한 부분을 그리는 원문 편집기를 사용한다. 읽기 모드도 전체 원문을 읽기 전용으로 표시한다. 대용량 문서의 서식 미리보기·사이드바 메타데이터·단어 수 계산은 안내와 함께 생략한다. 일반 문서의 실시간 꾸밈은 보이는 영역만 계산하고 변경되지 않은 노트의 메타데이터를 재사용한다. 캔버스 카드의 대용량 미리보기는 앞 8,000 코드 단위로 제한한다.

재검증: 같은 약 8.1MB 문서에서 편집·저장·다시 열기가 가능했고 저장 결과 전체가 기대 문자열과 일치했다. 19,600,018바이트 문서도 열기와 읽기 전환이 정상 동작했다. 캔버스의 대용량 파일 카드도 응답하며 전체 노트를 열 수 있었다.

## 시나리오 결과

| 시나리오 | 확인 방법 및 결과 |
| --- | --- |
| 새 노트 작성 | 실제 UI에서 생성, 한글·영문·이모지 붙여넣기와 Enter 줄바꿈, 저장 확인 |
| 본문 서식 | 선택한 English에 `⌘B` 적용, 저장 파일의 `**English**` 확인 |
| 일반 Markdown 읽기 | 제목·체크리스트·표·위키 링크 표시 확인 |
| 읽기 모드 왕복 | 입력 → 읽기 → 원본 → 실행 취소 → 다시 실행 재검증 통과 |
| 노트 탭 왕복 | A 수정 → B 열기 → A → 실행 취소 재검증 통과 |
| 체크박스 편집 | 읽기 화면 클릭 시 `[x]` 저장, 원본에서 실행 취소 시 `[ ]` 복원 |
| 입력 직후 탭 닫기 | 입력 직후 `⌘W`, 다시 열기 및 저장 파일에서 입력 내용 보존 확인 |
| 앱 종료 후 다시 열기 | 입력 내용을 저장한 뒤 메뉴에서 정상 종료, 최종 패키지로 다시 실행해 내용 복원 확인 |
| 외부 파일 변경 | 별도 프로세스가 추가한 내용 반영, 이전 실행 취소로 외부 내용을 되돌리지 않음 |
| 약 1.1MB 문서 | 열기·입력·실행 취소 확인 |
| 약 8.1MB 문서 | 입력·저장·읽기 전환·재실행 후 복원, 전체 바이트 일치 확인 |
| 약 19.6MB 문서 | 열기·읽기 전환 및 UI 응답 확인 |
| 캔버스 | 최종 패키지에서 일반 Markdown 카드와 대용량 파일 카드 표시, 파일 카드에서 전체 노트 열기 확인 |
| 저장 한도 | 자동 테스트에서 UTF-8 정확히 32MiB 저장·새 Vault로 재열기, 1바이트 초과 거부 및 기존 파일 보존 |

8.1MB 검수 문서의 최종 크기는 8,091,035바이트이며 SHA-256은 `a16224db0ce867725111e2f2091213c6c8763a8d41775caecdeeb91f6f983ed6`이다.

## 자동 검증과 패키지

- `npm test`: **48개 통과, 실패 0개**. 기존 41개에 편집 이력·외부 변경·캐시·대용량 Unicode·메타데이터·저장 한도 회귀 검증을 추가했다.
- `npm run package`: TypeScript 검사, 앱과 공유 페이지 빌드, macOS arm64 패키징 통과. 기존 번들 크기 경고는 남아 있다.
- `codesign --verify --deep --strict`: 통과. 기존 배포 방식과 같은 ad-hoc 서명이며 공증 배포는 아니다.
- 최종 `app.asar`로 별도 프로필을 실행해 저장 복원과 캔버스를 확인했다.
- 설치 파일: `release/Lithos-mac-arm64.zip`, 버전 **1.0.1**.
- 설치 파일 SHA-256: `05cd5ecf259f5467f20021015935cba158a3b5e4b8fe92cc77aac8442bc25538`.

## 적용 상태와 검증 범위

검수 종료 시 실제 사용 중인 앱은 재시작하지 않았다. 수정 소스와 설치 파일은 준비됐으며, 실행 중인 앱에 적용하려면 업데이트 후 재시작해야 한다. 임시 Quick Tunnel을 사용하는 공유 링크는 이때 외부 도메인이 바뀔 수 있다.

편집 이력은 앱 실행 중 메모리에 보관한다. 오래 사용하지 않은 노트는 개수·문자량 한도에 따라 이력이 해제되며, 앱 재실행이나 보관함 전환 후의 이력 복원은 제공하지 않는다. 대용량 원문 모드의 제한은 [사용 설명서](../Lithos_USER_GUIDE.md)에 반영했다.

물리 키보드의 한글 IME 조합 과정, 휴대폰 실기기, 디스크 공간 부족·전원 중단 상황, 대규모 그래프 성능은 이번 검수에서 직접 검증하지 않았다. 공유·동시 편집은 기존 자동 테스트를 통과했으며 이번에는 운영 공유 링크를 변경하는 실기기 테스트를 수행하지 않았다.
